# 코토바 정원 · ことばの庭

벚꽃, 전통 건축물, 책을 읽는 고양이와 함께 공부하는 일본어 단어 사이트입니다. **공개 사이트의 주소를 브라우저에서 열어 이용하는 방식**이며, 방문자는 Node.js 설치나 파일 다운로드 없이 PC와 스마트폰에서 공부할 수 있습니다.

## 설치 없이 웹에서 이용하기

공개 사이트 배포가 완료되면 GitHub Pages에 표시되는 사이트 주소로 접속합니다. 브라우저에서 그 주소를 즐겨찾기에 저장하면 다음에도 바로 열 수 있습니다. 아래 개발 명령과 로컬 실행 파일은 사이트 방문자에게 필요하지 않습니다.

**현재 공개 사이트의 정상 접속은 확인되지 않았습니다.** 이 README나 GitHub 저장소 링크는 안내·소스 페이지이며 공부 사이트가 아닙니다. 실제 접속 주소는 아래 Pages 설정을 저장한 뒤 배포 성공 화면의 **Visit site**에서 확인합니다.

### 저장소 소유자: GitHub Pages 설정

빌드 결과를 `gh-pages` 브랜치에 게시한 뒤 저장소 소유자가 한 번 설정합니다.

1. [Self 저장소의 Pages 설정](https://github.com/pty9945-tech/Self/settings/pages)을 엽니다.
2. **Build and deployment → Source**에서 **Deploy from a branch**를 선택합니다.
3. **Branch**를 `gh-pages`, 폴더를 `/(root)`로 선택하고 **Save**를 누릅니다.
4. GitHub Pages 배포가 성공하면 같은 화면에 표시되는 **Visit site** 주소를 엽니다. 홈 화면과 퀴즈가 실제로 열리는 것을 확인한 후 이 주소를 사용합니다.

`gh-pages`가 목록에 없다면 먼저 해당 브랜치에 빌드 결과가 게시되어 있어야 합니다. GitHub Actions에 Pages 빌드·배포 작업이 표시될 수 있으며, 완료까지 잠시 걸릴 수 있습니다. 저장소와 요금제에서 GitHub Pages를 사용할 수 있어야 합니다.

기본 주소로 예상되는 경로는 `https://pty9945-tech.github.io/Self/`입니다. 이 주소의 정상 동작은 아직 검증하지 않았으므로 **Pages 성공 화면에 표시된 주소를 기준으로** 접속하세요. 방문자가 GitHub API 허용 목록을 설정할 필요는 없습니다.

## 구현한 기능

- 단어 / 한국어 뜻 / 요미가나 중 무작위 한 칸을 직접 입력하는 퀴즈
- 히라가나·가타카나로만 된 단어는 단어 / 뜻 두 칸으로 출제
- 등록된 뜻과 동의어 인정, 뜻의 공백·문장부호 차이 허용
- 요미가나 입력 시 히라가나·가타카나 및 전각·반각 대응
- 연도별 단어장, 검색, CSV·JSON 가져오기와 JSON 내보내기
- 가져온 단어의 요미가나 확인·수정과 검수 상태 관리
- 오답 항목을 다시 출제하는 복습 노트, 학습 통계
- 브라우저 로컬 저장, 다양한 창 너비, 일본어 IME 조합 입력 대응
- 사이트에 포함된 글꼴과 SVG 일러스트. 런타임 외부 API 요청 없음

## 원본 자료 상태

현재 원본 단어 파일이 제공되지 않아 체험용 단어 22개만 포함했습니다. 모두 `sample`로 구분하며, 실제 연도나 출처를 부여하지 않았습니다. 원본 파일의 연도 분류와 의미에 따른 요미가나 대조는 아직 진행되지 않았습니다.

가져오기 기능은 CSV/JSON의 형식, 필수 항목, 가나 표기 형식을 검사합니다. **단어와 요미가나가 의미상 일치하는지는 자동 판정하지 않습니다.** 가져온 단어는 모두 검수 대기로 등록하며, 원문·사전으로 확인 후 저장한 단어만 퀴즈에 포함합니다. PDF, 이미지, XLSX 등은 현재 직접 가져오기를 지원하지 않습니다. 해당 원본을 별도로 정리·검수한 후 CSV/JSON으로 변환해야 합니다.

## 단어 파일 형식

UTF-8 CSV 예시입니다. 아래 연도는 형식 설명을 위한 예시입니다.

```csv
연도,단어,뜻,요미가나,동의어
2025,桜,벚꽃,さくら,
2025,優しい,상냥하다,やさしい,다정하다|친절하다
2024,コーヒー,커피,,
```

CSV의 `year,word,meaning,reading,acceptedMeanings` 영문 헤더도 사용할 수 있습니다. 뜻에 쉼표가 들어가면 큰따옴표로 감싸 주세요. 연도는 네 자리이며, 한자를 포함한 단어의 요미가나는 필수입니다. 파일은 최대 2MB입니다.

JSON은 다음과 같은 배열을 사용합니다.

```json
[
  { "year": "2025", "word": "桜", "meaning": "벚꽃", "reading": "さくら" },
  { "year": "2024", "word": "ありがとう", "meaning": "고마워", "acceptedMeanings": ["감사합니다", "고맙습니다"] }
]
```

내보낸 JSON을 다시 가져올 때도 검수 상태는 초기화됩니다. **단어 내보내기에는 학습 기록이 포함되지 않습니다.**

## 단어와 학습 기록 보관

단어와 학습 기록은 현재 브라우저의 `localStorage`에 저장되며 자동 동기화는 없습니다. 같은 PC에서도 다른 브라우저, 다른 프로필 또는 다른 주소로 열면 저장된 내용이 보이지 않을 수 있습니다. 항상 **같은 브라우저와 프로필에서 같은 사이트 주소**를 사용하세요. 공개 사이트와 로컬 사이트는 저장 공간이 다릅니다. 로컬에서 사용하는 `localhost`와 `127.0.0.1`도 서로 다른 주소로 취급되며 프로토콜이나 포트 번호가 달라도 저장 공간이 달라집니다.

일반 브라우저 창에서 사용하면 창을 닫았다가 같은 주소를 다시 열어도 기록이 남습니다. 시크릿 창을 닫거나 브라우저의 사이트 데이터를 삭제하면 기록이 지워질 수 있습니다. 필요한 단어는 JSON으로 별도 내보내어 보관하세요. 다른 주소나 기기에서 저장했던 단어를 옮기려면 이전 환경에서 JSON으로 내보낸 후 새 사이트에서 가져와야 합니다. 학습 기록은 이 방법으로 옮겨지지 않습니다.

## 선택 사항: 내 PC에서 실행하기

개발하거나 인터넷 없이 공부하려면 아래 로컬 실행 방법을 사용할 수 있습니다. 이 경우 서버는 `127.0.0.1:5173`에서만 열리므로 같은 와이파이의 스마트폰이나 다른 PC에서는 접속할 수 없습니다. 클라우드에서 서버를 실행해도 내 PC의 `localhost`로 접속할 수는 없습니다. 먼저 아래 방법으로 파일을 **사용할 PC에 다운로드하고 압축을 풀어 주세요.** README는 실행 안내 문서이며 사이트 자체가 아닙니다.

1. [Node.js 공식 사이트](https://nodejs.org/)에서 Node.js **24 LTS**를 설치합니다. 설치 후 열려 있던 터미널이 있다면 닫고 다시 엽니다.
2. [저장소](https://github.com/pty9945-tech/Self)의 **Code → Download ZIP**으로 소스를 받아 압축을 풉니다. `package.json`, `start-local.cmd`, `start-local.command`가 있는 폴더를 사용합니다.
3. Windows에서는 `start-local.cmd`를 더블클릭합니다. macOS에서는 터미널을 열어 해당 폴더로 이동한 다음 `bash start-local.command`를 실행합니다. Linux에서도 같은 명령을 사용할 수 있습니다.
4. 실행 창을 켜 둔 상태로 **그 PC의 브라우저 주소창**에 다음 주소를 입력합니다.

   ```text
   http://127.0.0.1:5173
   ```

종료하려면 실행 창에서 `Ctrl+C`를 누릅니다. 서버가 종료되면 접속도 중단됩니다. 다음에 공부할 때 실행 파일을 다시 열면 됩니다. 5173 포트를 이미 사용 중이라고 나오면, 이전에 열어 둔 실행 창을 먼저 종료하세요.

소스 ZIP에는 `dist/`가 없으므로 첫 실행 시 인터넷 연결을 사용해 의존성을 설치하고 사이트를 빌드합니다. 그다음부터는 완성된 사이트를 로컬에서 실행하며, 공부할 때 외부 API를 사용하지 않습니다. `dist/index.html`을 직접 더블클릭하는 대신 위 실행 파일을 사용하세요.

### GitHub에서 소스를 내려받은 경우

[저장소](https://github.com/pty9945-tech/Self)의 **Code → Download ZIP**으로 받는 파일에는 소스가 들어 있습니다. 압축을 풀고 위 실행 파일을 사용하면 `dist/`가 없는 첫 실행에 의존성 설치와 빌드가 진행됩니다. 이때는 인터넷 연결이 필요합니다.

직접 실행하려면 Node.js 24 설치 후 프로젝트 폴더에서 아래 명령을 순서대로 실행합니다.

```sh
npm ci
npm run build
npm start
```

사이트 주소는 동일하게 `http://127.0.0.1:5173`입니다. `npm start`는 이미 빌드된 `dist/`를 사용하므로 소스를 수정했을 때는 다시 빌드해야 합니다. 로컬 이용에는 GitHub API 연결 허용이나 GitHub Pages 설정이 필요하지 않습니다.

## 개발과 검증

React + TypeScript + Vite를 사용합니다. Node.js 24와 npm을 설치한 뒤 소스 폴더에서 실행합니다.

```sh
npm ci
npm run dev
```

개발 서버도 `127.0.0.1:5173`에서만 열립니다. 소스 수정은 개발 서버에서 바로 확인할 수 있습니다. 빌드 결과를 확인하려면 `npm run build` 후 `npm start` 또는 `npm run preview`를 사용하세요. 모두 같은 포트를 사용하므로 먼저 실행 중인 서버를 종료합니다.

```sh
npm test
npm run build
npm run test:e2e
```

브라우저 테스트는 기본적으로 클라우드에 설치된 `/usr/bin/chromium`을 사용합니다. 다른 환경에서 실행할 때는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 환경 변수로 설치된 Chromium 실행 파일의 경로를 지정하세요. 로컬 실행과 테스트에는 GitHub API가 필요하지 않습니다.
