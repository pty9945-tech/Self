# 코토바 정원 · ことばの庭

벚꽃, 전통 건축물, 책을 읽는 고양이와 함께 공부하는 반응형 일본어 단어 사이트입니다. React + TypeScript + Vite로 만들었으며, 별도 서버·데이터베이스·API 키 없이 정적 호스팅할 수 있습니다.

## 구현한 기능

- 단어 / 한국어 뜻 / 요미가나 중 무작위 한 칸을 직접 입력하는 퀴즈
- 히라가나·가타카나로만 된 단어는 단어 / 뜻 두 칸으로 출제
- 등록된 뜻과 동의어 인정, 뜻의 공백·문장부호 차이 허용
- 요미가나 입력 시 히라가나·가타카나 및 전각·반각 대응
- 연도별 단어장, 검색, CSV·JSON 가져오기와 JSON 내보내기
- 가져온 단어의 요미가나 확인·수정과 검수 상태 관리
- 오답 항목을 다시 출제하는 복습 노트, 학습 통계
- 브라우저 로컬 저장, 모바일 화면, 일본어 IME 조합 입력 대응
- 사이트에 포함된 글꼴과 SVG 일러스트. 런타임 외부 API 요청 없음

## 원본 자료 상태

현재 원본 단어 파일이 제공되지 않아 체험용 단어 22개만 포함했습니다. 모두 `sample`로 구분하며, 실제 연도나 출처를 부여하지 않았습니다. 원본 파일의 연도 분류와 의미에 따른 요미가나 대조는 아직 진행되지 않았습니다.

가져오기 기능은 CSV/JSON의 형식, 필수 항목, 가나 표기 형식을 검사합니다. **단어와 요미가나가 의미상 일치하는지는 자동 판정하지 않습니다.** 가져온 단어는 모두 검수 대기로 등록하며, 원문·사전으로 확인 후 저장한 단어만 퀴즈에 포함합니다. PDF, 이미지, XLSX 등은 현재 직접 가져오기를 지원하지 않습니다. 해당 원본을 별도로 정리·검수한 후 CSV/JSON으로 변환해야 합니다.

## 개발 실행

Node.js 22.12 이상 또는 24 이상과 npm이 필요합니다. 이 클라우드에서는 Node.js 24로 검증했습니다.

```sh
cd /workspace/Self
npm ci --cache /workspace/.npm-cache
npm run dev -- --port 5173 --strictPort
```

개인 컴퓨터에서는 프로젝트 폴더에서 `npm ci`, `npm run dev`를 실행하면 됩니다. 개발 서버는 `0.0.0.0`에 바인딩하므로 같은 네트워크의 스마트폰에서 컴퓨터의 LAN IP와 5173 포트로 접속할 수 있습니다. 외부 스마트폰 사용에는 아래 정적 배포가 필요합니다.

```sh
npm test
npm run build
npm run test:e2e
```

브라우저 테스트는 클라우드에 설치된 `/usr/bin/chromium`을 사용합니다. 다른 환경에서 실행할 때는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 Chromium 경로를 지정하거나 Playwright 설정을 설치한 브라우저 경로에 맞춰 주세요.

## 단어 파일 형식

UTF-8 CSV 예시입니다. 아래 연도는 형식 설명을 위한 예시입니다.

```csv
연도,단어,뜻,요미가나,동의어
2025,桜,벚꽃,さくら,
2025,優しい,상냥하다,やさしい,다정하다|친절하다
2024,コーヒー,커피,,
```

CSV의 `year,word,meaning,reading,acceptedMeanings` 영문 헤더도 사용할 수 있습니다. 뜻에 쉼표가 들어가면 큰따옴표로 감싸 주세요. 연도는 네 자리이며, 한자를 포함한 단어의 요미가나는 필수입니다. 파일은 최대 2MB입니다.

JSON은 다음과 같은 배열을 사용합니다.

```json
[
  { "year": "2025", "word": "桜", "meaning": "벚꽃", "reading": "さくら" },
  { "year": "2024", "word": "ありがとう", "meaning": "고마워", "acceptedMeanings": ["감사합니다", "고맙습니다"] }
]
```

내보낸 JSON을 다시 가져올 때도 검수 상태는 초기화됩니다. 단어와 학습 기록은 브라우저마다 별도로 저장되며 기기 간 자동 동기화는 없습니다. 단어 내보내기에는 학습 기록이 포함되지 않습니다.

## 스마트폰에서 사용하는 공개 사이트 배포

`npm run build` 결과인 `dist/`를 GitHub Pages, Cloudflare Pages, Netlify 등 HTTPS 정적 호스팅에 올리면 됩니다. 빌드 명령은 `npm run build`, 결과 폴더는 `dist`입니다. 상대 경로로 빌드하므로 하위 경로에서도 배포할 수 있습니다. 라우터 재작성이나 서버 환경 변수는 필요하지 않습니다.

이 README 링크는 사용 안내 문서를 엽니다. 클라우드 내부 개발 서버는 사용자 스마트폰에서 직접 접속할 수 있는 공개 주소가 아닙니다. 공개 배포는 아래 Pages 워크플로가 성공해야 완료되며, 사이트 주소는 배포 작업 출력에서 확인합니다.

### 준비된 GitHub Pages 배포

`.github/workflows/deploy-pages.yml`에 수동 배포 절차를 준비했습니다. 의존성 설치와 단위 테스트, 빌드를 통과한 결과만 배포합니다. 코드를 커밋하는 것만으로 자동 게시하지 않으며, 아래 작업이 완료되어야 실제 접속 주소가 생깁니다.

1. `pty9945-tech/Self` 저장소의 `main` 브랜치에 게시할 코드가 있는지 확인합니다.
2. 저장소의 Settings → Pages에서 Source를 GitHub Actions로 설정합니다. 저장소 공개 여부와 요금제에 따라 Pages 사용 가능 여부를 먼저 확인해야 합니다.
3. Actions → Publish Kotoba Garden → Run workflow를 실행합니다.
4. 배포가 성공한 뒤 `github-pages` 환경 또는 작업 출력에 표시되는 실제 URL을 확인합니다.
5. 해당 URL에서 홈 화면과 단어 입력·채점을 확인한 후 접속 주소를 공유합니다.

클라우드에서 이 절차를 진행하려면 GitHub API 접근이 필요합니다. 현재 Git 읽기는 정상이나 `api.github.com` HTTPS 연결은 네트워크 프록시에서 403으로 차단됩니다. API 허용 후 현재 제공된 인증의 저장소·Pages 권한을 확인해야 하며, 토큰을 채팅에 입력할 필요는 없습니다.
